# Принятые решения

Каждый пункт: что решили, почему, от чего отказались.

## Интерфейс — один HTML-файл без зависимостей

Открывается двойным щелчком, не требует сборки, легко переносится. Цена: весь код в одном файле, нет модулей и автотестов.

## Интерфейс независим от сервера

`index.html` — самостоятельная оболочка для любого сервера (по духу как mikupad). Свой сервер — необязательное дополнение, которое открывает больше данных. Отказались от варианта «интерфейс работает только со своим сервером»: тогда пропала бы простота запуска с LM Studio.

## Протокол LM Studio по умолчанию — `/v1/responses`

Так просили изначально, исходя из документации: логпробы есть только там. Проверка показала, что `/v1/chat/completions` тоже отдаёт логпробы и вдобавок учитывает все сэмплеры и seed. Оставлены оба протокола; по умолчанию `/v1/responses`, в настройках написано, чего в нём нет. Вопрос о смене умолчания открыт.

## Размышления LM Studio показываются без вероятностей

Сервер их не отдаёт. Вместо обходного режима (префилл `<think>`, после которого размышления приходят обычным текстом с логпробами) оставлено честное поведение и подсказка: перегенерация с позиции внутри размышлений даёт продолжение уже с вероятностями. Обходной режим меняет контекст модели и на MLX срабатывает не всегда.

## Свой движок — тонкий сервер поверх MLX, а не PyTorch

- Bonsai (27B, 2 бита) существует только в формате MLX и только так помещается в 16 ГБ.
- Модель в `mlx-lm` — обычный Python-код: доступны логиты и внутренние состояния.
- Цикл генерации свой, а токенизатор, шаблон чата, веса и кэш — из библиотеки.

Для Windows и Linux запланирован второй бэкенд на PyTorch за тем же протоколом.

## Свой протокол `/generate`, а не расширение OpenAI-формата

Нужны поля, которых в OpenAI-формате нет: id токенов, место в словаре, судьба кандидата на каждом этапе сэмплинга, принудительные токены. Совместимым оставлен только `/v1/models`, чтобы работала проверка соединения.

## Продолжение по id токенов

Клиент хранит id каждого токена и шлёт их в `prefix`. Повторная токенизация текста могла бы разбить его иначе, чем при генерации, и ветка стартовала бы из другого состояния.

## Вставка токена через `force`

Выбранный кандидат и свой текст сервер проводит через модель сам и возвращает со статистикой. Один механизм закрывает три задачи: ветвление, вставку своего текста и оценку произвольного текста (`max_tokens: 0`).

## Снимки кэша вместо обрезки

Архитектура Qwen3.5 не позволяет отмотать кэш. Снимки работают для любой архитектуры. Подробности — в [architecture.md](architecture.md).

## float32 для моделей в bfloat16

Иначе ветка не воспроизводит исходные вероятности. Для Qwen 0.8B цена — около 4% скорости и 0,2 ГБ памяти. Bonsai (float16) не трогаем: расхождение у него на уровне 1e-5, а перевод стоил бы 10% скорости и 1 ГБ.

## Порядок сэмплеров как в llama.cpp

Штраф за повторы → top-k → top-p → min-p → temperature. Так результаты сопоставимы с LM Studio и llama-server.

## Вероятность «у модели» и «после сэмплеров» показываются раздельно

`p` — распределение самой модели при температуре 1, `q` — шанс, с которым токен реально мог выпасть. Тепловая карта и объяснения опираются на `p`.

## Токен конца ответа — обычный токен

Свой сервер присылает его с кандидатами, клиент хранит с пометкой `end` и не включает в текст. Замена этого токена — способ заставить модель продолжить.

## Служебные токены видны по умолчанию

Они показаны плашками и кликабельны; иначе возможность заменить `</think>` или конец ответа никто бы не нашёл.

## Tab дописывает ответ на месте

Tab продолжает тот же узел, а не создаёт ветку: это пошаговое чтение одного ответа, а не развилка.

## Шаг генерации действует везде, по умолчанию выключен

Если шаг задан, столько токенов генерируется при любой генерации: первой отправке, ветке, продолжении. Ноль означает «весь ответ сразу». Сначала шаг действовал только на Tab и по умолчанию был 16; это оказалось неочевидно. Выбор шага вынесен под поле ввода.

## Окно токена в два уровня

При наведении — короткая карточка (вердикт и пять кандидатов), по клику — полная панель. Раньше всё показывалось сразу при наведении и не считывалось.

## Этапы отбора вместо двух колонок цифр

Сэмплеры показаны цепочкой этапов с числом выживших; на каждом этапе полосы кандидатов пересчитываются, выбывшие зачёркиваются. Строки на каждом этапе сортируются по текущей вероятности и плавно переезжают на новые места; слева стрелка показывает, на сколько позиций кандидат поднялся или опустился относительно предыдущего этапа, как в турнирной таблице. Штраф за повторы — отдельный этап: только он меняет порядок кандидатов. Для этого сервер отдаёт вероятность кандидата после top-k и доли, пережившие top-p и min-p.

## Панель токена не меняет размер и не закрывает токен

Блок с объяснением этапа и список кандидатов имеют постоянную высоту на всех этапах, иначе окно прыгало при переключении. Панель ставится под токеном, если не помещается — над ним, если и так нет — сбоку; в крайнем случае список ужимается под свободное место.

## Кандидаты за пределами списка подгружаются по запросу

В чате хранятся только главные кандидаты (иначе история быстро переполнит хранилище). По клику на «ещё N ток.» клиент просит сервер заново оценить тот же токен в той же позиции с длинным списком (`force` и `max_tokens: 0`); результат живёт только в памяти страницы.

## Энтропия как «число равных вариантов»

Вместо битов показывается 2^H: «как выбор из ≈2,8 равных вариантов». Биты остались в подсказке.

## Оформление: своя тема, без библиотек

Внешний вид собран на чистом CSS из нескольких переменных (фон, панели, линии, текст, акцент) с тёмно-синей и светлой темой. Правила, которых держимся:

- текст ответа — шрифт с засечками, весь интерфейс — системный без засечек, токены и формулы — моноширинный;
- рамка и заливка только у того, что является отдельным объектом (поле ввода, карточка шага, блок размышлений), а не у всего подряд;
- состояние показывается формой, а не только цифрой: цветная метка вердикта, плашки служебных токенов, подсвеченный активный пресет;
- подписи называют вещи с позиции пользователя («Лимит ответа», «Кандидатов на каждый токен»), а не именами параметров;
- когда средняя колонка сужается из-за открытых боковых панелей, шапка сама прячет второстепенные подписи (контейнерные запросы CSS).

Внешний сервис Claude Design для этого не использовался: он работает с отдельными дизайн-проектами, а не с кодом репозитория.

## Гифка в README собирается без сторонних программ

На машине нет ни ffmpeg, ни Pillow, а ставить пакеты вне окружения проекта нельзя. Кадры страница снимает сама (`tools/snap.js`): клонирует себя в SVG, рисует на холсте с двойным разрешением и отдаёт PNG без потерь. В GIF их переводит системная `sips`, а склеивает маленький скрипт `tools/join_gif.py`, который копирует сжатые данные кадров как есть. Первая версия собиралась из обычных снимков экрана браузерной панели и вышла мутной: те снимки уменьшены до 800 px и сжаты в JPEG. Цена нынешнего способа: гифка покадровая, без плавных переходов.

## Панель настроек открыта постоянно

Настройки — правая колонка, как список чатов слева; скрывается кнопкой, на экранах уже 1100 px становится выдвижной.

## Всё ставится в окружение проекта

Пакеты — в `.venv`, скачанные веса — в `models/`. Модели LM Studio читаются из его папки без копирования.
