# Принятые решения

Каждый пункт: что решили, почему, от чего отказались.

## Интерфейс — один HTML-файл без зависимостей

Открывается двойным щелчком, не требует сборки, легко переносится. Цена: весь код в одном файле, нет модулей и автотестов.

## Интерфейс независим от сервера

`index.html` — самостоятельная оболочка для любого сервера (по духу как mikupad). Свой сервер — необязательное дополнение, которое открывает больше данных. Отказались от варианта «интерфейс работает только со своим сервером»: тогда пропала бы простота запуска с LM Studio.

## Протокол LM Studio по умолчанию — `/v1/responses`

Так просили изначально, исходя из документации: логпробы есть только там. Проверка показала, что `/v1/chat/completions` тоже отдаёт логпробы и вдобавок учитывает все сэмплеры и seed. Оставлены оба протокола; по умолчанию `/v1/responses`, в настройках написано, чего в нём нет. Вопрос о смене умолчания открыт.

## Размышления LM Studio показываются без вероятностей

Сервер их не отдаёт. Вместо обходного режима (префилл `<think>`, после которого размышления приходят обычным текстом с логпробами) оставлено честное поведение и подсказка: перегенерация с позиции внутри размышлений даёт продолжение уже с вероятностями. Обходной режим меняет контекст модели и на MLX срабатывает не всегда.

## Свой движок — тонкий сервер поверх MLX, а не PyTorch

- Bonsai (27B, 2 бита) существует только в формате MLX и только так помещается в 16 ГБ.
- Модель в `mlx-lm` — обычный Python-код: доступны логиты и внутренние состояния.
- Цикл генерации свой, а токенизатор, шаблон чата, веса и кэш — из библиотеки.

Для Windows и Linux запланирован второй бэкенд на PyTorch за тем же протоколом.

## Свой протокол `/generate`, а не расширение OpenAI-формата

Нужны поля, которых в OpenAI-формате нет: id токенов, место в словаре, судьба кандидата на каждом этапе сэмплинга, принудительные токены. Совместимым оставлен только `/v1/models`, чтобы работала проверка соединения.

## Продолжение по id токенов

Клиент хранит id каждого токена и шлёт их в `prefix`. Повторная токенизация текста могла бы разбить его иначе, чем при генерации, и ветка стартовала бы из другого состояния.

## Вставка токена через `force`

Выбранный кандидат и свой текст сервер проводит через модель сам и возвращает со статистикой. Один механизм закрывает три задачи: ветвление, вставку своего текста и оценку произвольного текста (`max_tokens: 0`).

## Снимки кэша вместо обрезки

Архитектура Qwen3.5 не позволяет отмотать кэш. Снимки работают для любой архитектуры. Подробности — в [architecture.md](architecture.md).

## float32 для моделей в bfloat16

Иначе ветка не воспроизводит исходные вероятности. Для Qwen 0.8B цена — около 4% скорости и 0,2 ГБ памяти. Bonsai (float16) не трогаем: расхождение у него на уровне 1e-5, а перевод стоил бы 10% скорости и 1 ГБ.

## Порядок сэмплеров как в llama.cpp

Штраф за повторы → top-k → top-p → min-p → temperature. Так результаты сопоставимы с LM Studio и llama-server.

## Вероятность «у модели» и «после сэмплеров» показываются раздельно

`p` — распределение самой модели при температуре 1, `q` — шанс, с которым токен реально мог выпасть. Тепловая карта и объяснения опираются на `p`.

## Токен конца ответа — обычный токен

Свой сервер присылает его с кандидатами, клиент хранит с пометкой `end` и не включает в текст. Замена этого токена — способ заставить модель продолжить.

## Служебные токены видны по умолчанию

Они показаны плашками и кликабельны; иначе возможность заменить `</think>` или конец ответа никто бы не нашёл.

## Tab дописывает ответ на месте

Tab продолжает тот же узел, а не создаёт ветку: это пошаговое чтение одного ответа, а не развилка.

## Шаг генерации действует везде, по умолчанию выключен

Если шаг задан, столько токенов генерируется при любой генерации: первой отправке, ветке, продолжении. Ноль означает «весь ответ сразу». Сначала шаг действовал только на Tab и по умолчанию был 16; это оказалось неочевидно. Выбор шага вынесен под поле ввода.

## Окно токена в два уровня

При наведении — короткая карточка (вердикт и пять кандидатов), по клику — полная панель. Раньше всё показывалось сразу при наведении и не считывалось.

## Этапы отбора вместо двух колонок цифр

Сэмплеры показаны цепочкой этапов с числом выживших; на каждом этапе полосы кандидатов пересчитываются, выбывшие зачёркиваются. Строки на каждом этапе сортируются по текущей вероятности и плавно переезжают на новые места; слева стрелка показывает, на сколько позиций кандидат поднялся или опустился относительно предыдущего этапа, как в турнирной таблице. Штраф за повторы — отдельный этап: только он меняет порядок кандидатов. Для этого сервер отдаёт вероятность кандидата после top-k и доли, пережившие top-p и min-p.

## Панель токена не меняет размер и не закрывает токен

Блок с объяснением этапа и список кандидатов имеют постоянную высоту на всех этапах, иначе окно прыгало при переключении. Панель ставится под токеном, если не помещается — над ним, если и так нет — сбоку; в крайнем случае список ужимается под свободное место.

## Кандидаты за пределами списка подгружаются по запросу

В чате хранятся только главные кандидаты (иначе история быстро переполнит хранилище). По клику на «ещё N ток.» клиент просит сервер заново оценить тот же токен в той же позиции с длинным списком (`force` и `max_tokens: 0`); результат живёт только в памяти страницы.

## Энтропия как «число равных вариантов»

Вместо битов показывается 2^H: «как выбор из ≈2,8 равных вариантов». Биты остались в подсказке.

## Режим «Решение»: отдельный тип чата и лента прогонов

Исследование выбора из вариантов — это цикл «изменил запрос — посмотрел сдвиг», поэтому это не разговор, а лента прогонов с формой внизу. Форма остаётся заполненной после запуска; каждый прогон хранит свою копию запроса, любую карточку можно взять за основу. Карточка сама сравнивает себя с предыдущей: что изменено и на сколько пунктов сдвинулся каждый вариант (варианты сопоставляются по тексту, потому что место могло измениться).

Что решили по ходу:

- **Только обычные модели.** Берётся любая LLM, а не специальная «модель решений»: Laya и Clef устроены иначе (общий проход и отдельная голова-оценщик) и токены меток не читают.
- **Метка может быть записана разными токенами** («1», « 1», «1.»), поэтому карточка показывает три этапа: один токен → сумма написаний → пересчёт до 100%. Отдельно видно, сколько вероятности ушло мимо вариантов: пересчёт до 100% это скрывает.
- **Пропуск пробела.** У Qwen после «Ответ:» идёт отдельный токен-пробел, и без сдвига позиции метки получали бы доли процента. Сервер сдвигает позицию сам и сообщает об этом, карточка это показывает.
- **Размышления выключены:** иначе в позиции ответа модель начинает рассуждать.
- **Проверка устойчивости по кнопке**, а не при каждом прогоне: это ещё столько проходов, сколько вариантов, плюс один; на Bonsai проход занимает 2–3 секунды.
- **Циклические сдвиги вместо всех перестановок:** каждый вариант бывает на каждом месте, а число проходов растёт линейно.
- **Смещение меток** меряется проходом, где вопрос и варианты заменены прочерками.

## Оформление: своя тема, без библиотек

Внешний вид собран на чистом CSS из нескольких переменных (фон, панели, линии, текст, акцент) с тёмно-синей и светлой темой. Правила, которых держимся:

- текст ответа — шрифт с засечками, весь интерфейс — системный без засечек, токены и формулы — моноширинный;
- рамка и заливка только у того, что является отдельным объектом (поле ввода, карточка шага, блок размышлений), а не у всего подряд;
- состояние показывается формой, а не только цифрой: цветная метка вердикта, плашки служебных токенов, подсвеченный активный пресет;
- подписи называют вещи с позиции пользователя («Лимит ответа», «Кандидатов на каждый токен»), а не именами параметров;
- когда средняя колонка сужается из-за открытых боковых панелей, шапка сама прячет второстепенные подписи (контейнерные запросы CSS).

Для нынешнего `index.html` внешний сервис дизайна не использовался. Редизайн ведётся отдельно, см. следующий раздел.

## Редизайн: дизайн-система и компоненты в `ui/`, отдельно от `index.html`

Продукт растёт: к разговору и выбору из вариантов добавятся сравнение моделей, вычёркивание, взгляд внутрь модели и разные виды моделей. Нынешний интерфейс к этому не готов: около двадцати настроек одним списком, выбор «протокола» вместо модели, разделы в виде двух кнопок, одни и те же элементы сделаны дважды. Задание на редизайн — в `design-brief/BRIEF.md`.

Что решили:

- **Сначала общий язык, потом экраны.** Собрана дизайн-система: переменные оформления для двух тем, руководство и набор компонентов. Она опубликована страницей на claude.ai, а исходники лежат в `ui/`.
- **Реализация — React и TypeScript, стили — обычный CSS на переменных**, без библиотек компонентов. Для сборки нужны Node и пакеты в `ui/node_modules`; `index.html` при этом остаётся одним файлом без зависимостей и продолжает работать как раньше. Переход приложения на новые компоненты — отдельное будущее решение.
- **Навигация по задачам, а не по моделям.** Разделы — строки в боковой колонке («Разговор», «Выбор из вариантов», «Сравнение»…), под ними история текущего раздела. Кнопок «+ Чат» и «+ Решение» нет.
- **Пользователь выбирает модель, а не протокол.** В списке моделей у каждой написано, какие разделы она умеет; способ подключения приложение определяет само. Чего модель не умеет, того на экране нет — без серых неактивных элементов.
- **Один скелет: запрос → прогон → разбор.** Ответ в чате, карточка решения и будущие разделы ложатся в одну карточку прогона: вердикт и одна цифра, затем этапы, затем строки с полосами, затем подробности по клику. Два будущих раздела собраны без новых компонентов — так проверялось, что схема выдерживает рост.
- **Частое рядом, редкое убрано.** Температура, шаг и набор сэмплеров — под полем ввода; серверы, системный промпт, отображение и данные — в настройках из четырёх вкладок, не больше пяти полей на каждой.
- **Цвета поправлены ради читаемости.** В светлой теме затемнены приглушённый текст и цвета состояний, в тёмной текст на акцентной заливке стал тёмным (белый давал контраст 2.8:1), у полей ввода появился более заметный контур. Красно-зелёный градиент вероятности в систему не перенесён: подсветка и теплокарта одного оттенка. При проверке расчётом нашлись ещё два места ниже 4.5:1 — зелёная и оранжевая плашки-вердикты в светлой теме на фоне страницы (4.3:1); `ok` и `hot` светлой темы затемнены.
- **Вердикт: тон общий, слова — у каждого раздела свои.** Сначала словарь был один на всё, из пяти формулировок. Но разделы измеряют разное: уверенность в токене, согласие двух моделей, зависимость ответа от предложения, слой, на котором модель определилась. Общая формулировка «Ответ ненадёжен» не говорила бы, что именно нашёл раздел. Поэтому закреплён смысл трёх тонов (можно доверять, есть оговорки, полагаться нельзя), а формулировки записаны таблицей: одна на тон в каждом разделе. От варианта «свободный текст в плашке» отказались: одно и то же состояние начали бы называть по-разному.
- **Знак.** Три убывающих столбика: высокий цвета текста — выбранный токен, два пониже акцентные — кандидаты, которые модель могла взять вместо него.

От чего отказались: класть сборку во временную папку (пропадает вместе с сессией) и ставить пакеты глобально (нарушает правило «всё в окружении проекта»).

## Прежний интерфейс удалён, готовые серверы больше не поддерживаются

Интерфейс переведён на компоненты дизайн-системы (`ui/app/`), `index.html` удалён. Пользователю прежняя версия не нужна, а поддерживать две — значит делать каждую функцию дважды.

Что это меняет:

- **Правило «один файл без зависимостей» отменено.** Интерфейс теперь собирается: нужны Node и пакеты в `ui/node_modules`. Взамен — проверка типов, общие компоненты для всех разделов и одна дизайн-система.
- **Только свой сервер.** LM Studio и llama.cpp не перенесены: на них не работают этапы отбора и выбор из вариантов, а ветвление от ответа с размышлениями приближённое. Модели LM Studio в формате MLX сервер загружает сам. Раздел про независимость интерфейса от сервера выше описывает прежнее устройство.
- **Сервер раздаёт собранный интерфейс** из `ui/dist`; если он не собран, показывает страницу с командами сборки. Результат сборки в git не входит.
- **Данные прежней версии переносятся один раз, копией.** Обе версии открывались с одного адреса, поэтому новая пишет в свои ключи (`te2.db`, `te2.settings`), а старые только читает. Удалять старые ключи после переноса не стали: это единственная копия на случай ошибки в переносе.
- **Подсветка «градиент» не перенесена**: красно-зелёная шкала в дизайн-систему не вошла, остались «сомнения» и «энтропия».

Отказались от промежуточного варианта «новый интерфейс по адресу `/new/` рядом с прежним»: он прожил один шаг и нужен был, чтобы проверить новый на тех же данных.

## Раскладка: история слева, настройки справа

Первая версия нового интерфейса держала настройки отдельным экраном, частые параметры — чипами под полем ввода, а режимы — строками над историей. Пользователю это оказалось неудобно: настройки далеко, режимы сливаются с историей, под полем ввода шум. Теперь:

- **Три колонки.** Слева переключатель режима плитками, кнопка «начать новое» и история; справа настройки, открытые постоянно. Когда правая колонка не помещается (уже 1180px), она становится выдвижной и вызывается кнопкой в шапке.
- **Настройки — сворачиваемые группы** со значком и текущим значением в заголовке; пояснения к ним ушли во всплывающие подсказки. Серого поясняющего текста стало меньше везде: то, что сообщает факт, набрано основным цветом.
- **Свой набор значков** (`Icon`, линии, без библиотеки) вместо знаков Юникода, ползунок с заливкой, у температуры — шкала от холодного к горячему.
- **Формулы — своим компонентом** (`Formula`): курсив и дроби в два этажа. KaTeX не подключали: ради шести формул это около 300 КБ и новая зависимость.
- **Варианты переставляются перетаскиванием** за ручку (стандартное перетаскивание браузера, без библиотеки); с клавиатуры — стрелками.
- **Поверхности стали нейтральными** (графит вместо тёмно-синего), заголовки — без засечек; шрифт с засечками остался только у текста модели и формул.

## Общая история, режим у поля ввода, палитра ChatGPT

- **История одна на все режимы**, у каждого чата значок его вида.
- **Режимы — в левой колонке и названы технологией**: «LLM», «Decision Model». Пользователь собирается добавить разбор моделей генерации изображений, и названия по технологии к этому готовы, а «Разговор» и «Выбор из вариантов» — нет. Сначала режим выбирался меню у поля ввода, как инструменты в ChatGPT; пользователь предпочёл боковое меню, от которого зависит центр. У каждого режима свой открытый чат (`current.chat`, `current.choice`), `current.last` — выбранный режим; «Новый чат» всегда начинает LLM.
- **Боковые колонки скрываются одной кнопкой в шапке**, как в Claude Code; отдельного крестика внутри колонки нет.
- **Палитра нейтральная, как у ChatGPT**: серые поверхности без синего оттенка, главная кнопка монохромная (`fill`), наведение и выбор — серыми фонами `hover` и `selected` без цветных обводок и ореолов, синий — только для данных. Прежний сине-фиолетовый акцент на тёмно-синем фоне пользователь назвал главной причиной «ИИшного» вида.
- **Формула показывается вместе с числами** выбранного токена, расшифровкой букв и картинкой того, что отсекает фильтр; при смене этапа они появляются с анимацией.
- **Перетаскивание вариантов — на событиях указателя**, а не на встроенном перетаскивании браузера: только так соседние строки могут расступаться на лету и номера меняться до того, как строку отпустили.

## Меньше кнопок на виду

- **«Новый чат» — первая строка левой колонки**, без фона. Переименование, сохранение и удаление ушли из-под ленты в меню «⋯» у строки истории: действия над чатом живут там, где чат выбирают.
- **Под ответом — только значки** (как в ChatGPT и Claude): продолжить на шаг, дописать до конца (новое: генерация без учёта шага), другой вариант, копировать.
- **Карточка токена при наведении стала рабочей**: по ней можно провести указателем, выбрать кандидата и три действия значками. Из полной панели убраны плитки показателей и поле «свой текст» — в ней остался только разбор этапов. Поэтому у плавающего окна три состояния: наведение, удержание (пока вводится своё слово) и панель.
- **Форма Decision Model — тоже поле ввода**: вопрос, метки, варианты, стрелка отправки. Варианты правятся на месте и в свёрнутом виде; новый вариант добавляется пустой строкой, а не кнопкой. Инструкция, начало ответа и шаблон — за значком карандаша, по умолчанию скрыты.
- **Переключатель темы в шапке**: настройка `theme` (`system`, `light`, `dark`).
- Подпись «что модель могла сказать иначе» под названием убрана.

## Знак-развилка и последние правки раскладки

- **Новый знак** вместо трёх столбиков: путь ответа разветвляется, модель уходит по одной ветке (синей), две бледные — кандидаты, которые она могла взять. Нарисован в ChatGPT по нашему описанию; файлы — в `ui/design-system/project/assets/Logos/`, значок вкладки — тёмный вариант.
- **Режимы без подписей**, LLM переименован в «Language Model» — в одном ряду с «Decision Model».
- **Три действия с токеном — в шапке и карточки, и панели**, в порядке: подробнее, своё слово, заново отсюда. Карточка больше не прокручивается: прокрутка разрешена только панели, а окно пересчитывает положение, когда меняется его размер.
- **Поля формы Decision Model — тёмными полями**, у вопроса подпись «Вопрос», карандаш шаблона — рядом со стрелкой отправки.

## Мелочи формы и истории

- **Щелчок по режиму открывает в нём новый чат**; новый вопрос Decision Model — с пустым вопросом и двумя пустыми вариантами, а примеры, как у Language Model, — кнопками на пустом экране.
- **У чата есть время последнего запроса** (`updated`): в истории первой идёт дата со временем, затем число веток или прогонов. Строка при переименовании не меняет высоту — подпись остаётся под полем.
- **Поля ввода растут с текстом** (`useAutoGrow`): запрос Language Model — до 9 строк, вопрос Decision Model — до 6, дальше прокрутка внутри поля. У формы Decision Model прокручивается только содержимое, панель со стрелкой стоит на месте; место под полосу прокрутки зарезервировано (`scrollbar-gutter`), поэтому её появление ничего не сдвигает. Полосы прокрутки везде тонкие, в цветах темы.

## Режимы названы классом задачи, по-русски

«Language Model» и «Decision Model» заменены на «Генерация текста» и «Классификация текста»: режим — это класс задач, работу моделей в котором мы разбираем. Добавлена строка «Генерация изображений» с плашкой «Скоро» — задел на будущее; это сознательное исключение из правила не показывать недоступное. Левая колонка стала шире (288 px), чтобы самое длинное название помещалось в строку. Действия над прогоном классификации («проверить устойчивость», «взять за основу») — значками, как под ответом.

## Гифка в README собирается без сторонних программ

На машине нет ни ffmpeg, ни Pillow, а ставить пакеты вне окружения проекта нельзя. Кадры страница снимает сама (`tools/snap.js`): клонирует себя в SVG, рисует на холсте с двойным разрешением и отдаёт PNG без потерь. В GIF их переводит системная `sips`, а склеивает маленький скрипт `tools/join_gif.py`, который копирует сжатые данные кадров как есть. Первая версия собиралась из обычных снимков экрана браузерной панели и вышла мутной: те снимки уменьшены до 800 px и сжаты в JPEG. Цена нынешнего способа: гифка покадровая, без плавных переходов.

## Панель настроек открыта постоянно

Настройки — правая колонка, как список чатов слева; скрывается кнопкой, на экранах уже 1100 px становится выдвижной.

## Всё ставится в окружение проекта

Пакеты Python — в `.venv`, пакеты npm — в `ui/node_modules`, скачанные веса — в `models/`. Модели LM Studio читаются из его папки без копирования. Глобально стоит только сам Node.
