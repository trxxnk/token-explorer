# Идеи на будущее

Порядок внутри разделов — примерно по пользе.

## Согласовано, не начато

- **Logit lens.** Для выбранного токена показать, каким был бы прогноз после каждого слоя: на каком слое модель «определилась». Нужен доступ к выходам слоёв в `MLXBackend`.
- **Карты внимания.** На какие предыдущие токены смотрела модель. В Qwen3.5 обычное внимание есть только в каждом четвёртом слое, остальные слои рекуррентные.
- **Бэкенд на PyTorch** для Windows и Linux за тем же протоколом. На этом Mac проверить можно только Qwen 0.8B на процессоре, не на NVIDIA.

## Интерфейс после переезда

Интерфейс переведён на компоненты из `ui/` (решение — в [decisions.md](decisions.md)).

- **Новые разделы**, для которых уже есть макеты в дизайн-системе: «Сравнение», «Вычёркивание», «Внутри модели».
- **Плавная пересортировка строк** при смене этапа: сейчас меняется только длина полос.
- **Автотесты** для `ui/app/logic.ts` (этапы отбора, вердикты, промпт выбора): расчёты отделены от экрана как раз для этого.
- **Статистика запроса**: сколько токенов взято из кэша, время загрузки модели.
- **Показатели токена** (место в словаре, неопределённость, шанс после фильтров) убраны из панели вместе с плитками; решить, где их показывать.
- Проверить на Bonsai и на ответах в несколько тысяч токенов.

## Модели решений

- **Другие подходы к выбору из вариантов.** Раздельные эмбеддинги со скалярным произведением (есть `nomic-embed-text` в LM Studio) и модели с общей головой-оценщиком: Laya (ModernBERT, GGUF 449 МБ) и Clef-Flash (Qwen3.5-9B, MLX 4 бит 6,2 ГБ). Для них нужны новые зависимости (`laya`, `mlx-vlm`) и загрузки — с согласия пользователя.
- **Вычёркивание.** Убирать из текста по предложению и смотреть сдвиг вероятностей: показывает, какие места решили исход, и работает для любого подхода.
- **Сначала порассуждать, потом выбрать:** прогон с размышлениями и чтением меток после них.
- **Несколько вопросов к одному тексту и типы вопросов** (да/нет, шкала), как у Laya и Clef.
- **Свои метки** у вариантов, например «да» и «нет».
- **Сравнение двух моделей** на одном запросе в одной карточке.

## Хранение истории

Сейчас всё в `localStorage`: лимит около 5 МБ.

- Перенести в IndexedDB (сотни мегабайт, без зависимостей).
- Вариант для своего сервера: хранить чаты файлами в папке проекта, общими для всех браузеров.

## Свой сервер

- **Полное распределение по запросу.** Сейчас подгружаются следующие 25 кандидатов; дальше — сотни и тысячи, поиск токена по тексту.
- **Сравнение моделей.** Один и тот же текст через две модели, разница вероятностей по токенам.
- **Вмешательство в активации** (steering): усиление или подавление направлений во внутренних состояниях.
- **Промежуточные снимки кэша** во время генерации, чтобы ветка в конце длинного ответа Bonsai не пересчитывала весь ответ.
- **Выбор точности** ключом запуска (сейчас float32 включается автоматически для bfloat16).
- **Raw-режим в интерфейсе.** Сервер уже принимает `prompt`, интерфейс его не использует.
