# AGENTS.md

Правила и контекст для ИИ-агентов, которые работают с этим репозиторием. Описание проекта для людей — в [README.md](README.md), подробности — в [docs/](docs/).

## Что это за проект

Token Explorer — инструмент для изучения того, как локальная LLM выбирает токены. Две части:

- `server.py` — сервер с собственным циклом генерации на MLX; он же раздаёт интерфейс.
- `ui/` — интерфейс на React и TypeScript (`ui/app/`), компоненты и дизайн-система (`ui/src/`, `ui/design-system/`).

Интерфейс работает только со своим сервером. Прежняя версия — один файл `index.html` с поддержкой LM Studio и llama.cpp — удалена и осталась в истории git; не возвращать её и не добавлять готовые серверы без просьбы пользователя.

## Жёсткие правила

1. **Всё ставится в окружение проекта.** Пакеты Python — только в `.venv`, пакеты npm — только в `ui/node_modules`, веса — только в `./models`. Системный Python и глобальные пакеты (в том числе `npm install -g`) не трогать.
2. **Новая зависимость — только с согласия пользователя**, с названием и размером. `server.py` использует стандартную библиотеку плюс `mlx-lm` и `numpy` (обновлять `requirements.txt`); интерфейс — React, TypeScript и esbuild, без библиотек компонентов, CDN и внешних шрифтов (обновлять `ui/package.json`).
3. **`.venv/`, `models/`, `ui/node_modules/` и результаты сборки (`ui/dist`, сборка дизайн-системы) не коммитить.** Скачивание моделей согласовывать с пользователем, называя имя и размер.
4. **Язык.** Интерфейс, документация и общение с пользователем — на русском. Комментарии в коде — на английском; исключение — комментарии к свойствам компонентов в `ui/src`, они на русском.
5. **Объяснения простым языком.** Пользователь не специалист по внутренностям инференса: термин сопровождать практическим следствием.
6. **Данные пользователя в браузере не удалять.** Его чаты лежат в `localStorage` по адресу `localhost:8090`: ключи `te2.db`, `te2.settings`, `te2.migrated`, а также `te.db` и `te.settings` прежней версии (единственная копия на случай ошибки переноса). Никогда не очищать хранилище целиком.

## Как запускать и проверять

- Сборка интерфейса: `npm run app` в `ui/` (перед первым запуском `npm install`). Она проверяет типы и пишет `ui/dist`. Сервер: `.venv/bin/python server.py`, затем http://localhost:8090.
- После правок в `ui/app` или `ui/src` пересобрать и перезагрузить страницу; сервер перезапускать не нужно. После правки `server.py` — перезапустить сервер.
- **Проверять на своём экземпляре: `.venv/bin/python server.py --port 8091`.** У другого адреса своё хранилище браузера, чаты пользователя не затрагиваются, а его сервер не нужно перезапускать. После проверки удалить созданные там ключи `te2.*`.
- Если порт 8090 занят, скорее всего, пользователь сам запустил сервер в терминале: второй экземпляр на нём не поднимать.
- Состояние страницы не глобальное: проверять кликами, чтением страницы и ключами `localStorage`.
- Движок можно гонять без HTTP: `server.Engine(server.MLXBackend()).generate({...})` возвращает генератор событий.
- Автотестов нет. Минимальная ручная проверка после изменений: генерация, карточка и панель токена, ветка от кандидата, свой текст, «заново отсюда», Tab, второй ход диалога, ответ с размышлениями, прогон выбора из вариантов с проверкой устойчивости.

## Карта кода

| Файл | Содержимое |
|---|---|
| `ui/app/logic.ts` | расчёты без React и сети: типы данных, `stagesFor()`, `stageRows()`, `tokenVerdict()`, `answerVerdict()`, `choiceVerdict()`, `heatLevel()`, `choicePrompt()` |
| `ui/app/store.ts` | `state`, `bump()`, хранилище и перенос данных прежней версии (`migrateOld()`), запросы: `generate()`, `send()`, `branchAt()`, `continueLast()`, `fetchMore()`, `runChoice()`, `checkChoice()` |
| `ui/app/main.tsx` | экраны (`Conversation`, `Choice`, `App`), правая панель настроек (`SettingsPanel`), панель токена (`TokenDetails`, `TokenCard`, `Float`), формы (`ChatDock`, `ChoiceDock`) |
| `ui/src/` | компоненты дизайн-системы и `styles.css` |
| `ui/build-app.mjs`, `ui/build.mjs` | сборка интерфейса и сборка дизайн-системы |

`server.py`: `MLXBackend` (модель, токенизатор, кэш и его снимки), `analyze()` (один шаг сэмплинга с полным описанием решения), `Engine` (рабочий поток, цикл генерации `generate()`, один проход без генерации `score()`), `Handler` (HTTP, SSE и раздача `ui/dist`).

## Папка ui

Компоненты, интерфейс и исходники дизайн-системы. Страница дизайн-системы: https://claude.ai/artifact/DTjz29eenMSWXeBmMer9p8.

- `ui/src/` — компоненты (`base.tsx`, `analysis.tsx`, `shell.tsx`) и `styles.css`; `ui/demos/all.tsx` — примеры для превью; `ui/design-system/project/` — то, что публикуется (переменные оформления, руководство, описания, логотипы); `ui/build.mjs` — сборка.
- Сборка: `npm run build` в `ui/` (перед первым запуском `npm install`). Проверяет типы и пишет `bundle.js`, `bundle.css`, `index.d.ts`, копию исходников и `preview.html` каждой карточки в `ui/design-system/project/components/`. Эти файлы в git не входят.
- **Значения оформления — только в `tokens.json`.** В `styles.css` цвета, отступы и скругления берутся через переменные; новое значение сначала заводится в `tokens.json` с пояснением, где оно используется.
- **Текст на любом фоне — контраст не ниже 4.5:1 в обеих темах** (3:1 для контуров полей и крупных цифр). Первая тема в `tokens.json` — тёмная, она основная.
- **Новый раздел не заводит своих компонентов результата**: он заполняет `RunCard`, `StageChain`, `CandidateRow`, `HeatTable`. Если не получается — это повод обсудить с пользователем, а не добавить вариант.
- **Вердикт: тон общий, формулировка — из таблицы раздела** в руководстве (`ui/design-system/project/README.md`). Новый раздел сначала добавляет туда свою строку: по одной формулировке на тон.
- **Интерфейс (`ui/app/`) собирает экраны только из компонентов `ui/src`.** Своих стилей у него нет; раскладка — атрибутом `style` без значений оформления (цвета, скругления — только через переменные).
- **Компоненты не хранят состояние** (кроме открытия колонки в `AppShell`) и не знают о теме и сервере.
- Комментарии к свойствам компонентов — на русском: они показываются на странице дизайн-системы как документация. Остальные комментарии в коде — на английском.
- Публикация — инструментом Artifact с корнем `ui/design-system`, только изменённые файлы; `.ts` и `.tsx` — с типом `text/plain`; `design-system.json` — последним и только если менялся. После публикации открыть страницу в браузерной панели и просмотреть изменённые карточки (пользователь вошёл там в claude.ai).
- Перед правкой `tokens.json` и описаний прочитать их текущую версию со страницы: пользователь может менять значения прямо там.

## Инварианты, которые легко сломать

- **Токен на клиенте** — объект `{t, id, p, top[], ...}`; поля описаны в [docs/architecture.md](docs/architecture.md). В чатах, перенесённых из прежней версии, есть токены без `id` и этапов и с лишними полями (`np`, `r`, `b`): код не должен на них падать.
- **Сравнение токенов** — через `same(a, t)` (по `id`, если есть), а не по тексту: фрагменты одного символа выглядят одинаково.
- **Текст ответа** собирать через `tokensText()`: он пропускает токен конца.
- **Продолжение идёт по id токенов** (`exPrefix()`), а не по тексту. Синтетические токены (`syn`) и токен конца в префикс не попадают.
- **Вся работа с MLX — в одном потоке** (`Engine._work`). Массивы MLX привязаны к потоку, в котором созданы.
- **Кэш модели нельзя «отмотать»**: у Qwen3.5 большинство слоёв рекуррентные. Вместо этого — снимки кэша (`prime()`, `marks`).
- **Модели в bfloat16 при загрузке переводятся в float32**, иначе ветка не воспроизводит исходные вероятности.
- **Порядок сэмплеров** как в llama.cpp: штраф за повторы → top-k → top-p → min-p → temperature.
- **Шаг генерации** (`settings.step`, 0 — весь ответ) применяется в `generate()` ко всем запросам, а не только к Tab.
- **Панель токена не должна менять размер** при переключении этапов и не должна закрывать сам токен: блок объяснения и список кандидатов имеют фиксированную высоту, положение считает `Float`.
- **Кандидаты сверх сохранённых** подгружаются `fetchMore()` и живут только в памяти (`moreCache`); в чат их не записывать — хранилище ограничено.
- **Чат бывает двух видов.** У выбора из вариантов `kind: 'decision'`, поля `runs` и `form`, а дерево `nodes` пустое; код, который обходит все чаты, должен это учитывать.
- **Никаких `prompt()`, `confirm()`, `alert()`**: во встроенном браузере они запрещены и бросают ошибку. Ввод и подтверждение — элементами на странице.
- **Состояние меняется на месте, экран узнаёт об этом через `bump()`.** Забытый `bump()` — экран не обновится; `saveDb()` — изменение не переживёт перезагрузку.
- **Формат настроек и чатов менять через миграцию** (`settings.v`): у пользователя есть сохранённые данные.
- **Старые ключи `te.db` и `te.settings` только читать** (`migrateOld()`), не писать и не удалять.
- **Протокол сервера** описан в [docs/server-protocol.md](docs/server-protocol.md); при изменении обновлять документ и обе стороны.

## Документация

При заметных изменениях обновлять:

- `README.md` — возможности, запуск, ограничения;
- `docs/decisions.md` — новое решение и его причина;
- `docs/problems-solved.md` — найденная и исправленная проблема;
- `docs/roadmap.md` — сделанное убрать, новые идеи добавить;
- `docs/architecture.md` и `docs/server-protocol.md` — при изменении формата данных, полей токена или протокола;
- `ui/README.md` и описания в `ui/design-system/project/` — при изменении компонентов, сборки или переменных оформления;
- этот файл — при появлении нового правила или инварианта.

## Демонстрация в README

`docs/demo.gif` собирается из кадров, которые страница снимает сама, без потерь: `tools/snap.js` рисует страницу в PNG с двойным разрешением и отправляет в `tools/frame_receiver.py`; затем `sips --resampleWidth 1600 -s format gif` переводит кадры в GIF, а `tools/join_gif.py` их склеивает (всё на стандартной библиотеке и системных утилитах). Обычные снимки экрана из браузерной панели для этого не годятся: они уменьшены и сжаты, текст выходит мутным. Съёмка — на отдельном порту, в окне 1440×900 (уже 1180 px правая колонка прячется), в тёмной теме; `snap.js` отключает анимации, иначе на кадре они начинаются с прозрачного первого кадра. После заметных изменений интерфейса гифку переснять.

## Git

Коммиты и отправка на GitHub — по просьбе пользователя. Сообщения на русском, в повелительном или назывном стиле, с пояснением «зачем».

**Перед каждым коммитом — обязательная проверка:**

1. Просмотреть весь diff (`git status`, `git diff`) и вспомнить, что обсуждалось и решалось по ходу работы.
2. Оценить важность каждого изменения и решения: что изменило поведение, протокол, формат данных, правила работы; от каких вариантов отказались и почему; какие проблемы нашлись и как решены.
3. Убедиться, что всё важное отражено в документации (см. раздел «Документация») и что документация не описывает того, чего в коде уже нет. Недостающее дописать до коммита, в тот же коммит.
4. В сообщении коммита перечислить важное, а не каждую правку.
