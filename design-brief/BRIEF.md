# Token Explorer: задание на редизайн

Это пакет для Claude Design: задание, снимки нынешних экранов (`screens/`) и текущий интерфейс одним файлом (`index.html`).

## Что это за продукт

Token Explorer — локальный инструмент для изучения того, как языковая модель принимает решения. Он не помогает получить ответ, он показывает, как ответ получился: из каких вариантов модель выбирала каждое слово, насколько сомневалась и что было бы, выбери она иначе.

Кто пользуется: один человек на своём компьютере, которому интересно устройство моделей. Он не обязательно специалист по машинному обучению, поэтому каждое число и термин должны объясняться простыми словами.

Работает в браузере на настольном экране, с локальными моделями. Язык интерфейса — русский.

## Что нравится и должно сохраниться

- Тёмно-синяя тема как основная; светлая тоже нужна.
- Текст ответа модели набран шрифтом с засечками, интерфейс — без засечек, токены и формулы — моноширинным.
- Цепочка этапов с числом выживших кандидатов и объяснением «простой текст + формула + пример».
- Список кандидатов как турнирная таблица: полосы, места, стрелки, плавная пересортировка.
- Цветные вердикты простыми словами: «Уверенный выбор», «Есть сомнения», «Ответ ненадёжен».
- Два уровня подробностей: коротко при наведении, полностью по клику.

## Главная задача

Продукт будет расти: новые способы разбора и новые типы моделей. Нужен интерфейс, который остаётся простым и не перегруженным, когда разделов станет шесть-семь, а моделей — десяток разных видов.

Сегодняшние слабые места:

1. **Панель настроек** — около двадцати элементов одним списком, часть неактивна в зависимости от подключения. Каждая новая функция добавляет ещё.
2. **Подключение** — пользователь выбирает «протокол» из пяти вариантов. Это внутренняя кухня; ему нужно выбрать модель.
3. **Разделы** — их два, и они устроены как две кнопки «+ Чат» и «+ Решение». Для шести так не получится.
4. **Нет общего языка компонентов** — строка с полосой, цепочка этапов, карточка результата сделаны дважды и немного по-разному.
5. **Плотность** — полная панель токена и карточка решения содержат много всего сразу.

## Что появится дальше

Интерфейс должен выдержать добавление этого без перестройки:

- **Другие способы выбора из вариантов.** Раздельные эмбеддинги вопроса и вариантов; специальные «модели решений» (Laya, Clef), которые за один проход выдают вероятность каждого варианта.
- **Вычёркивание.** Убирать из текста по предложению и показывать, как меняется ответ: какие места текста решили исход.
- **Сравнение моделей.** Один и тот же запрос через две модели, разница рядом.
- **Внутри модели.** На каком слое модель «определилась» с токеном; на какие предыдущие слова она смотрела.
- **Несколько вопросов к одному тексту** и типы вопросов: выбор, да/нет, оценка по шкале.
- **Каталог моделей.** Обычные LLM, модели эмбеддингов, модели решений; у каждой свой набор доступных разделов.
- **История и хранение.** Чаты и прогоны, импорт и экспорт.

## Принципы, которых хочется держаться

1. **Навигация по задачам, а не по моделям.** Разделы названы тем, что человек хочет изучить: «Разговор», «Выбор из вариантов», «Сравнение», «Внутри модели». Модель — параметр внутри раздела.
2. **Один скелет для всех разделов:** запрос → прогон → разбор по этапам. Освоил один раздел — понятны остальные.
3. **Показывать только доступное.** Чего подключённая модель не умеет, того на экране нет; никаких серых неактивных элементов с пояснениями.
4. **Подробности по запросу.** Сначала ответ и одна цифра, глубже — по клику.
5. **Частое рядом, редкое убрано.** Температура и шаг генерации — у поля ввода; адрес сервера — в настройках, которые открывают редко.
6. **Каждое число объяснено.** Рядом с цифрой — что она значит простыми словами.

## Что нужно получить

1. **Каркас приложения** на шесть-семь разделов: навигация, выбор модели с её возможностями, место для истории, место для настроек.
2. **Единый шаблон «прогон и разбор»**, в который ложатся и ответ в чате, и карточка решения, и будущие разделы.
3. **Набор компонентов:** кнопки, переключатель, поле, плашка-вердикт, плашка токена, строка кандидата с полосой, цепочка этапов, плитка показателя, таблица-теплокарта, карточка, всплывающая панель, пустое состояние.
4. **Экраны:** разговор с ответом; панель токена; выбор из вариантов с прогоном и проверкой; выбор и подключение модели; настройки; и один-два будущих раздела (сравнение моделей, вычёркивание), чтобы проверить, что схема выдерживает рост.
5. **Переменные оформления:** цвета обеих тем, размеры шрифтов, отступы, скругления.

## Ограничения

- Реализация будет на React и TypeScript, стили — обычный CSS на переменных. Готовые библиотеки компонентов и CSS-фреймворки нежелательны.
- Только системные шрифты, без загрузки внешних.
- Настольный экран от 1100 px шириной — основной; на узком должно оставаться пригодным.
- Анимации — умеренные и осмысленные: они объясняют, что изменилось, а не украшают. Уважать настройку «уменьшить движение».
- Интерфейс полностью на русском.
